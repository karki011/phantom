Risk Assessment

Ghostty libghostty API instability
Feature-flag behind //go:build ghostty tag. xterm.js fallback always works. Surface code already handles API changes via callback stubs.
OSC 633 parser adds PTY latency
Parse in a separate goroutine on the fan-out channel, not in the hot read path. Benchmarks before/after — target <1ms overhead per write.
Assistant prompt size explosion
Hard cap at 8KB with tiered priority system (already in SessionMemoryBuilder). Context window budget enforcement per signal source.
Persona "uncanny valley"
Start minimal — workspace awareness first, personality second. Terse and helpful beats chatty and clever. Let users configure verbosity.
Session memory storage grows unbounded
TTL-based cleanup already in schema (extractor defines 60-180 day TTLs). Add compaction schedule. FTS5 index size is naturally bounded.
Cross-platform shell integration divergence
OSC 633 is a standard (used by VS Code, Warp, iTerm2). Go parser is protocol-level, not shell-specific. Fish support is the only gap.

Recommended First Move

Start Phase 0 + Phase 1 in parallel.


The memory Store fix is a 15-minute change. Adding git context to the AI pipeline is ~1 hour. The Go-side OSC 633 parser (~200 lines) is the single highest-leverage piece — it turns every terminal session into a stream of structured intelligence.


Without signals flowing, the Phantom Persona (Phase 2) has nothing interesting to say. Data first, personality second.
